# 技术文章写作与 Hexo 发布

## 确定任务和环境
从用户指定位置或当前工作区定位 Hexo 根目录，读取适用的 AGENTS.md、_config.yml、package.json 和 Git 状态。
区分“写草稿”“更新文章”和“发布文章”。已有发布授权可继续执行，不重复索取确认；源码提交/推送需用户请求或会话授权。
不硬编码账户、目录、发布分支或主题，不覆盖无关修改。

## 写作
阅读 [references/writing-and-release.md](references/writing-and-release.md) 中对应阶段的指导。
主题有歧义时结合上下文解释采用的含义。需要事实资料时实际访问可靠来源；没有联网能力时说明限制。
注明来源，区分事实、归纳与假设案例。不要编造作者经历、项目指标或测试结果。
在 source/_posts 下创建或编辑文章，使用 UTF-8、有效 YAML 元信息及合理摘要。日期按用户时区；保留既有文章的日期和地址，除非用户要求调整。

## 校验和构建
使用现有 Node.js 及 Hexo 项目中的 js-yaml 运行：
node "<skill-dir>/scripts/check-post.cjs" "<hexo-root>" "<post-file>"
脚本只检查常见文章格式和文件范围，不替代 Hexo 构建或内容事实核对；没有现有依赖时不要静默安装。
执行项目已有构建命令，并定位实际生成地址。核对标题、关键章节、引用、本地下载附件及首页入口。
命令退出失败时停止依赖步骤，先定位问题。

## 发布与交付
只有任务包含发布时，才按项目现有配置部署。不得为了发布自行更换远端、修改 CI、升级依赖或扩大访问权限。
部署后检查线上地址和实际内容。页面尚未更新时进行少量有间隔的检查；仍无法确认则明确报告“推送成功，线上待确认”。
在已获授权时仅提交本次相关文件，汇报文章 URL、源码路径、检查结果和实际完成的 Git 操作。
