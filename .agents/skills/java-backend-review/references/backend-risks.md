# Java/Spring 审查线索

只查与当前变更相关的条目。以下是排查方向，不是自动成立的缺陷。

## 鉴权与数据隔离
- 用户 ID 来自请求参数还是可信身份？查询是否包含当前用户或租户约束？
- 修改或删除资源时是否检查所有权？缓存键是否包含隔离维度？
- 能否用另一用户的资源 ID 构造可复现的越权请求？

## 事务
- 调用是否经过实际事务代理？默认代理模式下，同类自调用通常不会触发新事务拦截；确认代理模式再下结论。
- 异常是否被捕获后吞掉？回滚规则是否覆盖实际异常类型？
- 数据库与消息/缓存是否跨越事务边界？不要假设本地事务涵盖外部服务。

## 并发与幂等
- 是否存在先查询再写入的竞争窗口？唯一约束、锁或原子更新是否真的覆盖它？
- 重试是否重复产生业务副作用？幂等键和业务结果是否关联保存？
- 对乐观锁更新是否检查受影响行数？

## 缓存、查询与分页
- 缓存失效与数据库更新的先后顺序是否引入可复现的陈旧值？
- 查询条件和缓存键是否一致？空结果和过期策略是否合理？
- 分页是否稳定排序且限制大小？批量逻辑是否产生实际的 N+1 查询？

## 异常与外部调用
- 超时、连接池、资源关闭和有限重试是否覆盖真实调用路径？
- 日志是否暴露凭证或敏感数据？错误信息是否让调用者误判为成功？
